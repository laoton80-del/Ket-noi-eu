# P0-A1 — Cost Governor Phase B: atomic reserve / settle design

> **Status:** design only. This document neither authorizes nor contains a migration, source-code change, provider call, database call, deployment, or commit. It was prepared against integration commit `d2223d8ff7a3fd30ff2d4ecdfdf0e372e40ac9f4`.
>
> **Citation convention:** every statement about the current implementation cites `file:line` in that baseline. “Proposed” items are future design decisions; their citations identify the existing boundary or precedent that motivates them.
>
> **Terminology:** this document calls the user-facing token **VIO** and calls the separate balance **credit**. Existing source identifiers such as `balanceVIG`, `lockedBalanceVIG`, `amountVIG`, and `tokensBurned` are quoted verbatim only as current code/schema names; this design does not rename them. The Cost Governor records platform-provider cost only, in integer micro-USD, and does not debit, reserve, convert, or reconcile VIO/credit balances.

## 1. Executive decision

Phase B should introduce one fail-closed **Cost Governor Authority** that atomically reserves the maximum permitted provider exposure *before* any paid outbound call, then settles or releases that reservation after the outcome is known. The authority must be the only writer of its ledger and budget counters; a provider SDK, an Express controller, and a Firebase function must not update separate cost totals. This closes the present gap in which the Express router calls OpenAI and only then starts an asynchronous usage-log write, while Firebase proxies call OpenAI/Gemini without a shared reserve/settle step. (`src/services/ai/AIRouterService.ts:53-73`, `src/services/ai/AIRouterService.ts:88-114`, `functions/src/index.ts:303-323`, `functions/src/index.ts:473-523`)

The recommended canonical store is a new **PostgreSQL/Prisma ledger**, accessed by Express directly and by Firebase through one private, authenticated Cost Governor Authority RPC. This is a design recommendation, not a claim that the two rails already share storage: the Prisma datasource is PostgreSQL and Express creates its client from `DATABASE_URL`, whereas Cloud Functions initialize Firestore and currently keep a distinct `wallets/{uid}` credit shape. (`prisma/schema.prisma:4-12`, `src/lib/prisma.ts:18-43`, `functions/src/index.ts:14-20`, `functions/src/index.ts:47`, `functions/src/index.ts:573-581`)

This is not merely a static “hard-dollar circuit breaker.” It is a lifecycle ledger that accounts for **reserved** as well as **settled** exposure, carries an idempotency key, distinguishes provider acceptance from a usable product outcome, and uses atomic counters for user/day, global/day, and global/month policy. The existing special-purpose circuit breaker is not a substitute: it is attached to an explicitly unwired adapter and its query reads post-call token logs for one isolated task type. (`src/lib/viona/realProviderAdapter/vionaOpenAiRealProviderAdapter.ts:1-20`, `src/lib/viona/realProviderAdapter/vionaOpenAiRealProviderAdapter.ts:81-85`, `src/services/viona/vionaProviderSpendWindowQueryService.ts:139-170`)

### 2.2 Existing usage, wallet, credit, and idempotency records

`LlmApiUsageLog` stores task type, selected model, optional input/output/total token counts, timestamp, and optional user ID. `AIRouterService` writes it only after receiving a completion, launches that write without awaiting it, and catches a write failure locally; it therefore cannot be a pre-call fail-closed reservation ledger. (`prisma/schema.prisma:861-876`, `src/services/ai/AIRouterService.ts:53-73`, `src/services/ai/AIRouterService.ts:101-112`)

Prisma also has a `Wallet` with existing `balanceVIG`/`lockedBalanceVIG` fields and a generic `Transaction` ledger whose optional unique idempotency key is described as preventing duplicated AI/billing debits. Those current user-token records are useful precedents, but their schema has no provider/model/usage/reserve/settle lifecycle fields. (`prisma/schema.prisma:453-484`)

`AILog` is a separate Prisma audit model with a user, persona, action, and the existing `tokensBurned` field. It should not be repurposed as the authoritative Phase-B ledger without a separately approved schema and lifecycle decision. (`prisma/schema.prisma:878-891`)

Express already has a serializable, conditional-decrement VIO wallet-debit primitive with a transaction idempotency check. Its documented sequence is pre-flight balance check followed by a separate post-inference debit, which is valuable precedent but is not an atomic reservation around the current `AIRouterService` provider call. Phase B must not couple its platform-cost ledger to that user balance. (`src/services/ai/AIGateway.ts:39-62`, `src/services/ai/AIGateway.ts:72-102`, `src/services/WalletService.ts:1868-1943`, `src/services/ai/AIRouterService.ts:88-114`)

Firebase separately stores credits in Firestore `wallets/{uid}` and already demonstrates atomic `runTransaction` patterns for idempotent top-ups, charges, and generic holds. Its generic `reserve` operation deducts credits and writes a `holds/{key}` document, while `commit`/`rollback` update that hold; `aiProxy` and `analyzeDocumentProxy` do not invoke this flow today. ## 3. Proposed authoritative model

### 3.1 Ledger entities and units

**Proposed:** add a dedicated Prisma model family in a separately approved migration; do not overload `LlmApiUsageLog`, `AILog`, `Wallet`, `Transaction`, or Firestore `holds`. The first three are telemetry/audit or user-credit records, and the latter two stores presently have incompatible ownership and value shapes. (`prisma/schema.prisma:453-484`, `prisma/schema.prisma:861-891`, `functions/src/index.ts:573-581`, `functions/src/index.ts:758-796`)

| Proposed entity | Required fields and invariant |
| --- | --- |
| `AiCostOperation` | Immutable `operationId`; unique `(rail, idempotencyKey)`; canonical subject/tenant; provider; model; task/operation; price-version ID; request bounds; `reservedMicrousd`; `settledMicrousd`; and status `RESERVED`, `DISPATCHING`, `SETTLED`, `RELEASED`, or `OUTCOME_UNKNOWN`. It is the one lifecycle record for a provider attempt and retry. The unique idempotency pattern follows the current Prisma `Transaction.idempotencyKey` and Firestore hold-key precedents. (`prisma/schema.prisma:466-484`, `functions/src/index.ts:758-796`) |
| `AiCostLedgerEntry` | Append-only event per operation: `RESERVE`, `SETTLE`, `RELEASE`, or `ADJUSTMENT`, in non-floating integer `microusd`, with prior/new operation state, timestamp, and actor/system reason. The immutable-event rule prevents a successful provider attempt from being erased by a later timeout handler. The need for a separate lifecycle comes from current post-call-only logging and generic wallet ledgers. (`src/services/ai/AIRouterService.ts:53-73`, `prisma/schema.prisma:466-484`) |
| `AiCostBudgetCounter` | One row per `scope + windowStart`: user/day, global/day, and global/month. It contains only `reservedMicrousd` and `settledMicrousd`; it contains no cap value and no VIO/credit field. Reservation increments reserved exposure; settlement converts/reconciles it; release removes only unused reserve. This replaces the current per-instance Firebase counter for budget correctness. (`functions/src/aiProxyRateLimit.ts:1-32`) |
| `AiModelPrice` | Versioned provider/model price row with effective interval, input/output/audio/image unit rules, currency/unit, and an explicit maximum-reserve calculation version. A missing or ambiguous row means deny, never a guessed free price. Current model selection and the isolated illustrative rate table show why the exact model must be recorded rather than inferred later. (`src/services/ai/AIRouterService.ts:20-39`, `src/services/viona/vionaProviderSpendWindowQueryService.ts:117-131`) |

All Cost Governor amounts use integer micro-USD, never JavaScript floating-point values. User VIO and Firestore credit remain separate commercial balances and are out of Phase B; the current records use different units and fields. (`prisma/schema.prisma:453-484`, `functions/src/index.ts:573-581`)

### 3.1.1 Runtime-only cap policy

**Proposed:** the three cost caps are runtime environment configuration, not Prisma fields, migrations, database rows, or seed data. The governor parses all three before `reserve()`; a missing, non-positive, or unparsable value yields `DENY_UNCONFIGURED` and zero provider dispatch. This follows the existing fail-closed environment-policy style, while avoiding a cap that is accidentally enabled by a seed/default row. (`src/services/ai/llmProviderAdmissionGate.ts:1-10`, `src/services/ai/llmProviderAdmissionGate.ts:51-78`, `functions/src/index.ts:99-110`)

| Proposed runtime variable | Scope | Pilot value proposed by Operator | Missing or `0` |
| --- | --- | ---: | --- |
| `VIONA_COST_GOVERNOR_USER_DAILY_CAP_MICRO_USD` | One canonical user per UTC day | `500000` | DENY |
| `VIONA_COST_GOVERNOR_GLOBAL_DAILY_CAP_MICRO_USD` | Whole platform per UTC day | `12000000` | DENY |
| `VIONA_COST_GOVERNOR_GLOBAL_MONTHLY_CAP_MICRO_USD` | Whole platform per UTC calendar month | `250000000` | DENY |

The pilot values are runtime deployment inputs for the Operator to set during implementation; they are not values to place in a migration, a seed, or a VIO/credit balance. (`prisma/schema.prisma:4-12`, `functions/src/index.ts:99-110`, `functions/src/index.ts:573-581`)

### 3.2 Atomic reservation algorithm

**Proposed:** before an outbound paid-provider request, the caller computes only trusted request bounds (selected provider/model, validated token/image/audio size, operation class, canonical subject, and idempotency key) and calls `reserve()`. That ordering preserves the current principle that denial happens before SDK/provider work. (`src/services/ai/AIRouterService.ts:83-104`, `src/services/marketing/ViralWrapEngine.ts:69-99`, `functions/src/index.ts:269-323`, `functions/src/index.ts:426-503`)

Within one serializable Prisma transaction, `reserve()` must do all of the following atomically:

1. Read or create the operation by its unique idempotency key. A repeated key returns the same operation and does not create a second reserve; a key reused with different immutable request fields returns `409 idempotency_conflict`. The current wallet debit and Firestore hold transactions provide the repository’s atomic/idempotent precedent. (`src/services/WalletService.ts:1879-1931`, `functions/src/index.ts:758-796`)
2. Resolve exactly one effective price row and compute a conservative maximum exposure from validated request limits and model-specific pricing. Missing price, unsupported model, malformed bounds, or unavailable policy configuration returns `DENY_UNCONFIGURED` before dispatch. Existing routes already cap request shape and model selection, so those validated values—not arbitrary client values—are the input to this calculation. (`src/services/ai/AIRouterService.ts:20-39`, `src/controllers/AIController.ts:271-325`, `functions/src/aiProxyValidation.ts:61-135`, `functions/src/index.ts:447-503`)
3. Parse and require the three positive runtime caps, then lock/read the user/day, global/day, and global/month counter rows; test each `settled + reserved + proposedReserve <= runtimeCap`; write the `RESERVE` ledger entry, operation, and counters in the same transaction. A database race therefore permits at most the exposure covered by the counters, rather than both concurrent callers observing the same stale remaining balance. The existing wallet debit uses serializable isolation plus conditional decrement for the same reason. (`src/services/WalletService.ts:1868-1943`, `src/services/ai/llmProviderAdmissionGate.ts:51-78`)
4. Commit the database transaction **before** the provider call. A provider call must never run inside that transaction; it is an external, nondeterministic action, while the existing provider call and database-write paths are independent operations. (`src/services/ai/AIRouterService.ts:53-73`, `src/services/ai/AIRouterService.ts:88-114`)

The committed operation ID/idempotency key must be carried to a provider as correlation or idempotency metadata where that provider API supports it; where it does not, the governor still owns deduplication and forbids a blind resend after an ambiguous dispatch. This extends the repository’s existing durable idempotency pattern to the pre-provider boundary instead of treating a post-call usage log as proof of a unique attempt. (`prisma/schema.prisma:466-484`, `src/services/WalletService.ts:1879-1943`, `functions/src/index.ts:758-796`, `src/services/ai/AIRouterService.ts:53-73`)

If the governor’s database transaction, policy lookup, or internal authority RPC fails, the rail returns a truthful `503 cost_governor_unavailable` and does **not** construct/call an OpenAI/Gemini client. This makes ledger failure fail-closed, consistent with the existing admission gate’s fail-closed policy and the current ordering before provider construction. (`src/services/ai/llmProviderAdmissionGate.ts:1-10`, `src/services/ai/AIRouterService.ts:83-104`, `src/services/marketing/ViralWrapEngine.ts:69-99`)

### 3.3 Settlement and release

**Proposed:** after the provider attempt, `settle()` uses the same operation key and a serializable transaction to record actual provider usage/cost when available, decrement/convert its outstanding reserve, and write `SETTLE`; any surplus reserve is released in the same transaction. `release()` is permitted only when the service can prove the request was never dispatched or the provider definitively rejected it without billable acceptance. The logged provider model and usage fields make exact post-response settlement possible where the response reports usage, but current telemetry must not be treated as sufficient proof because its persistence is detached and best-effort. (`src/services/ai/AIRouterService.ts:53-73`, `src/services/ai/AIRouterService.ts:101-112`)

`providerAccepted` and `productSucceeded` must be separate facts. A 2xx/accepted provider response that yields empty, malformed, or unusable output is a **failed product outcome** even if it may be billable; current ViralWrap and Gemini code already distinguish a transport success from a valid result. The governor must settle the provider exposure according to returned usage or the reserve ceiling, while the API returns an honest error rather than a fake success. (`src/services/marketing/ViralWrapEngine.ts:113-117`, `functions/src/index.ts:504-523`)

### 3.4 Explicit timeout policy

| Observation after a reservation | Proposed ledger action | Client/result policy |
| --- | --- | --- |
| Validation, pricing, reserve, or local pre-dispatch check fails | No reserve or `RELEASE` if a reserve already committed and the system can prove no outbound send occurred. | Deny/error; no provider call. This preserves the present pre-provider validation ordering. (`src/services/ai/AIRouterService.ts:91-104`, `functions/src/index.ts:303-323`, `functions/src/index.ts:447-503`) |
| Provider explicitly rejects before acceptance | `RELEASE` the unused reserve, with the provider error classification. | Return the truthful upstream failure; do not retry through another paid rail automatically. Current proxies already return upstream errors rather than success. (`functions/src/openaiProxy.ts:10-16`, `functions/src/openaiProxy.ts:24-30`, `functions/src/index.ts:504-510`) |
| Provider returns accepted/2xx but usable outcome validation fails | `SETTLE` actual reported usage; if unavailable, settle the conservative reserved amount and flag reconciliation. | Return failure; accepted is not success. (`src/services/marketing/ViralWrapEngine.ts:113-117`, `functions/src/index.ts:513-523`) |
| Timeout/connection loss after dispatch cannot be disproved | Set `OUTCOME_UNKNOWN`, retain the reserve for the proposed default **24 hours**, block a new paid dispatch for the same key, and return `503 cost_outcome_unknown` (never success). | A reconciler may settle returned provider usage; it may release only on affirmative evidence of no dispatch. |
| `OUTCOME_UNKNOWN` reaches its 24-hour TTL with no affirmative no-dispatch proof | Settle the full reserve conservatively, record `SETTLED_CONSERVATIVE` detail, and alert for review; do not auto-release. | This protects global/user caps from an ambiguous bill. Operator may later authorize an audited adjustment, never an invisible mutation. |

The timeout rules deliberately mean **Timeout != Success**. They also prohibit a blind cross-rail retry: a Firebase timeout must not fall back to Express or vice versa, because either request might have reached a billable provider. Current routing already treats upstream errors as failures; Phase B must preserve that truthfulness while adding durable accounting. (`functions/src/index.ts:326-360`, `functions/src/index.ts:504-523`, `src/services/ai/AIRouterService.ts:83-87`)

## 4. One source of truth across Express and Firebase

### 4.1 What is true today

There is no demonstrated common cost ledger today. Express uses the PostgreSQL Prisma datasource and has user-token and usage models, while Cloud Functions depend on `firebase-admin`, initialize Firestore, and use Firestore credit documents/transactions. The Functions package does not declare `@prisma/client`, so simply importing the Express Prisma service into Functions is not an established or safe integration path. (`prisma/schema.prisma:4-12`, `src/lib/prisma.ts:18-43`, `prisma/schema.prisma:453-484`, `functions/package.json:16-23`, `functions/src/index.ts:14-20`, `functions/src/index.ts:47`, `functions/src/index.ts:573-581`)

Therefore Phase B must not attempt a distributed “update Prisma + update Firestore + call provider” transaction. Instead, the Cost Governor Authority owns exactly one canonical PostgreSQL/Prisma ledger and exposes only idempotent `reserve`, `settle`, `release`, and `readOperation` commands. Firebase uses a private, service-authenticated authority RPC before every OpenAI/Gemini dispatch and again afterward; it does not independently mutate cost counters in Firestore. This proposal uses the repository’s existing serializable Prisma transaction precedent while avoiding two-store ownership. (`src/services/WalletService.ts:1868-1943`, `functions/src/index.ts:609-628`, `functions/src/index.ts:758-796`)

Express calls the authority in-process or through the same private contract; Firebase uses the same contract, canonical subject mapping, model-price version, idempotency key, and error vocabulary. If the private Firebase-to-authority identity/transport cannot be provisioned and tested, the safe alternative is to keep Firebase paid provider paths disabled or route the entire request to the single authority/executor. It is not safe to enable a second Firestore-only ledger and reconcile it later. The current per-instance rate bucket expressly cannot provide global correctness. (`functions/src/aiProxyRateLimit.ts:1-32`)

### 4.2 Fail-closed boundary contract

**Proposed authority responses:**

| Authority result | Required caller behavior |
| --- | --- |
| `ALLOW_RESERVED(operationId, reserveVersion)` | The sole condition that permits one provider dispatch for that operation. |
| `DENY_CAP`, `DENY_POLICY`, `DENY_IDENTITY`, or `DENY_UNCONFIGURED` | No outbound provider call; return a truthful denial code/status. |
| `DUPLICATE_IN_PROGRESS` or `OUTCOME_UNKNOWN` | No second paid dispatch; return the existing operation state / retry-after guidance without a fake result. |
| timeout, database error, malformed authority response, or internal-RPC authentication failure | Treat as `DENY_LEDGER_UNAVAILABLE` and return 503; no outbound provider call. |

This contract is intentionally stricter than the current Firebase in-memory limiter and current best-effort usage write: a failed ledger write is a dispatch blocker, not a log message after the spend. (`functions/src/aiProxyRateLimit.ts:1-32`, `src/services/ai/AIRouterService.ts:53-73`)

## 7. Non-negotiable acceptance criteria for Phase B

- A cap/policy/identity/ledger failure results in a truthful deny/error and **zero outbound provider calls**. This extends the current P0-A0 ordering from admission to durable cost reservation. (`src/services/ai/llmProviderAdmissionGate.ts:51-102`, `src/services/ai/AIRouterService.ts:83-104`, `src/services/marketing/ViralWrapEngine.ts:69-99`)
- Repeated requests with the same idempotency key produce one operation and never a second paid dispatch while the first outcome is unresolved. The design follows existing transaction/hold idempotency patterns but applies them before provider dispatch. (`prisma/schema.prisma:466-484`, `src/services/WalletService.ts:1879-1943`, `functions/src/index.ts:758-796`)
- Concurrent requests cannot collectively reserve more than any configured user/day, global/day, or global/month cap; reserve, ledger entry, and counter updates are one serializable transaction. The existing serializable wallet transaction is the implementation precedent. (`src/services/WalletService.ts:1868-1943`)
- A provider acceptance/transport response is not reported as product success until output validation succeeds; ambiguous outcomes retain a durable state and reconcile conservatively. (`src/services/marketing/ViralWrapEngine.ts:113-117`, `functions/src/index.ts:504-523`)
- Firebase chat, STT, TTS, and Gemini document analysis use the same authority contract as Express OpenAI; the current per-instance rate limit remains a throughput control only, not a cost source of truth. (`functions/src/index.ts:303-323`, `functions/src/index.ts:409-523`, `functions/src/aiProxyRateLimit.ts:1-32`)
